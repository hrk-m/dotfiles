# コミュニケーション
- 日本語で応答する（コード・変数名は英語）
- 簡潔に回答し、自明な説明は省略する
- 複雑なタスクでは実装前に計画を提示し、承認後に着手する

# コードスタイル
- 関数型アプローチを優先し、副作用を最小化する
- 厳密な型付け（anyは使わずunknownを使う）
- エラーは握りつぶさず、意味のあるメッセージ付きで処理する

# Git規約
- Conventional Commits形式、本文は日本語（例: `feat: ユーザー認証にOAuth2を追加`）
- 確認なしに自動コミット・自動pushしない

# 禁止事項
- README・ドキュメントを勝手に生成・変更しない
- テストコードを確認なしに削除・コメントアウトしない
- 既存の動作するコードを理由なくリファクタリングしない

## ~/src リポジトリハーネス

- `~/src` 配下のリポジトリで作業を開始するときは、まず `~/src/HARNESS.md`（自動生成のリポジトリ地図）を読み、対象リポジトリの位置づけを確認する
- アクティブなリポジトリの詳細（目的・アーキテクチャ・コマンド・注意点）は `~/src/.harness/repos/<host>/<org>/<repo>.md` にある。作業前に必ず読む
- 地図が実態とずれていたら `/harness-sync` を実行して同期する（~/src 配下のセッション終了時にも自動同期される）
- リポジトリ作業中にハマった点・非自明な制約を見つけたら、該当する `~/src/.harness/repos/<path>.md` の「## 注意点」内「### 運用知見（セッション由来）」に `- [日付] 知見` 形式で追記する（セッションからの自動抽出もされるが、その場で書く方が確実）
